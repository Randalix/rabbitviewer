# Video Thumbnail Implementation

## Overview

Video thumbnails and the brief pre-playback "view image" are both generated by
invoking **mpv** as a CLI subprocess. The live hover preview (in
`gui/video_view.py`) uses the `python-mpv` binding against the same decoder
and scaler, so the cached frame and the first hover frame come from the same
pipeline — eliminating the color/scale drift that existed when thumbnails went
through ffmpeg and hover went through mpv.

Metadata (duration, width, height, codec) still comes from **ffprobe** — it is
cheap, has no visual impact, and the JSON interface is simpler than parsing
mpv's `--print-metadata` output.

## Dependencies

| Tool | Used for | How it's invoked |
|---|---|---|
| `mpv` | thumbnail + view-image frame extraction | CLI subprocess in `plugins/video_plugin.py` |
| `mpv` (libmpv) | live hover playback | `python-mpv` binding in `gui/video_view.py` |
| `ffprobe` | duration, dimensions, codec | CLI subprocess in `plugins/video_plugin.py` |

Both must be on PATH. `VideoPlugin.is_available()` checks both.

## Cache layout

Frames land at the standard `BasePlugin` locations:

```
{cache_dir}/thumbnails/{md5}.jpg   # scaled, thumbnail_size cap
{cache_dir}/images/{md5}.jpg       # native size
```

## Invalidating the ffmpeg-era cache

`VideoPlugin.cache_version = 2` triggers the per-plugin migration in
`ThumbnailManager._check_per_plugin_cache_migration()` (see
`core/thumbnail_manager.py`). On first run of the new code:

1. The marker file `{cache_dir}/plugin_cache_versions.json` is compared
   against each plugin's `BasePlugin.cache_version` class attribute.
2. For any plugin whose version bumped (including "missing from marker"
   treated as version 1), `ImageTable.clear_thumbnail_paths_for_extensions()`
   NULLs `thumbnail_path` / `view_image_path` for rows whose file extension
   matches that plugin's supported formats.
3. The corresponding on-disk JPEGs are deleted.
4. The marker is rewritten with the new versions.

Only video files are invalidated — image thumbnails from `PILPlugin`,
`CR3Plugin`, etc. stay intact. On the next grid access of an affected video,
mpv regenerates the thumbnail on demand; the background indexer picks up the
rest on the next directory scan.

To invalidate your own plugin's cache later, set `cache_version = N+1` on the
plugin class. No code changes needed elsewhere.

## mpv command shape

Thumbnail (scaled):

```
mpv --no-config --really-quiet --no-terminal --no-audio --no-sub \
    --start=<seek> --frames=1 \
    --of=image2 --ovc=mjpeg \
    --ovcopts=strict=unofficial --ofopts=update=1 \
    --vf=scale=w=<size>:h=<size>:force_original_aspect_ratio=decrease \
    --o=<out.jpg> <input>
```

View image is identical but omits `--vf`.

### Flag rationale

- **`--no-config`** — ignores the user's `~/.config/mpv/mpv.conf` so output is
  deterministic across machines.
- **`--of=image2 --ovc=mjpeg`** — encode the post-filter frame as JPEG via the
  same decode + swscale path the hover uses.
- **`--ovcopts=strict=unofficial`** — ffmpeg's mjpeg encoder rejects non-full-
  range YUV in strict mode; relaxing is required and produces output
  byte-compatible with a standard JPEG decoder.
- **`--ofopts=update=1`** — single-file output without the image2 sequence
  warning.
- **`--start=<seek>`** — 10% of duration (falls back to 2.0s if duration is
  unknown). Matches the old ffmpeg behavior; this is what you want the
  thumbnail to show, independent of the hover start.
- **`--frames=1`** — single frame, then exit.

## Seek time

`_seek_time()` returns `max(duration * 0.1, 0.0)` or `2.0` if ffprobe can't
read the duration. Same policy as before.

## Error handling

`subprocess.run(..., timeout=30, check=True)`. Any `SubprocessError` is logged
and the method returns `None`; callers already handle the absent-thumbnail
case.

## Tests

`tests/test_video_plugin.py` synthesizes a 2-second `testsrc` mp4 via ffmpeg's
lavfi source and verifies:

- `is_available()` returns True
- thumbnails land in `thumbnails/v2/`
- view images land in `images/v2/`
- `thumbnail_size` is an upper bound on both output axes
- cache-hit path does not re-run mpv (mtime unchanged)
- ffprobe-based metadata still works

Tests are skipped when either `mpv` or `ffmpeg` is missing from PATH.

## Known residual difference

The live hover overlay is rendered by libmpv's OpenGL video output with tone
mapping applied; the cached JPEG goes through the same decode + swscale but
not the GL tone-mapping step. In practice the delta is small (and both sides
are now consistent across machines). If it becomes noticeable, append
`format=yuv420p,colorspace=bt709` to the filter chain on both paths.
